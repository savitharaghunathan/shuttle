# shuttle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Go binary `shuttle` that runs PR-factory and SDLC pipelines as YAML DAGs with pluggable workers (shell/exec/agent presets), human approval gates, SQLite state, and a localhost HTTP API sharing one engine.

**Architecture:** `cmd/shuttle` → config + store + pipeline engine + worker registry. Each run uses project `cwd` for code changes and `.shuttle/runs/<id>/` for inputs/artifacts/logs/approvals. One DB at `.shuttle/shuttle.db`. Manual stages block the run until `approve`/`reject`. CLI is primary; `serve` binds `127.0.0.1:8080` only.

**Tech Stack:** Go 1.22+, Cobra, `gopkg.in/yaml.v3`, `modernc.org/sqlite`, `go-chi/chi/v5`, `text/template`, stdlib `testing`.

**Spec (source of truth):** [design.md](./design.md) ← synced from root [PLAN.md](../../PLAN.md)

## Global Constraints

- Name/CLI/config/data/module all `shuttle`; module `github.com/savitharaghunathan/shuttle`
- Git remote: `git@github.com:savitharaghunathan/shuttle.git` (push only when user asks)
- No vendor SDKs in core — config-driven argv presets only
- Single-writer SQLite; no run-level resume/`shuttle retry` in v0
- Gates before `open_pr` and `ship`; those commands default to safe `echo` (exit 0)
- HTTP: `127.0.0.1:8080`, no auth
- TDD per task: failing test → implement → pass → commit
- **Commit style:** every commit uses `git commit -s` (Signed-off-by / DCO). Not `-S` (no GPG/SSH crypto sign required by this plan).
- **Assisted-by trailer:** every commit message ends with `Assisted-by: <model>` (e.g. `Assisted-by: Cursor <cursoragent@cursor.com>`). Use the actual model name that did the work.
- Trust: workers run as invoking user; document in README

### Task 6: Engine (schedule, gates, cancel, retries)

**Files:**
- Create: `internal/pipeline/engine.go`, `engine_test.go`

**Interfaces:**
- Consumes: store, registry, config, artifact, validate/ready/render
- Produces:

```go
type Engine struct {
	Store    *store.Store
	Registry *worker.Registry
	Cfg      *config.Config
}
func (e *Engine) StartRun(ctx context.Context, p StartParams) (runID string, err error)
func (e *Engine) Tick(ctx context.Context, runID string) (blockedOrDone bool, err error)
func (e *Engine) RunUntilBlockOrDone(ctx context.Context, runID string) error
func (e *Engine) Approve(runID, stageID, message string) error
func (e *Engine) Reject(runID, stageID, message string) error
func (e *Engine) Cancel(runID string) error
```

`StartParams`: `TemplateID`, `Pipeline *Pipeline`, `CWD`, `SpecPath string`

Behavior (must match design.md):
- Roots → `ready`; dispatch up to `Concurrency`
- `worker==manual` → `waiting_approval`, run `blocked` (no Execute)
- Success → materialize outputs under `artifacts/`, unlock dependents
- Fail + attempts ≤ retries → backoff 2s → `ready`; else fail run, skip pending/ready
- Timeout via context on worker
- Approve → succeeded + `approvals/<stage>.md` + unblock
- Reject → rejected, run failed, skip rest
- Cancel → cancel in-flight, running→cancelled, pending/ready/waiting_approval→skipped, run→cancelled
