# shuttle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `shuttle`, a Go CLI/HTTP control plane that runs ticket→PR and full-SDLC pipelines as YAML DAGs with pluggable agent workers and human approval gates.

**Architecture:** Single binary (`cmd/shuttle`) owns one SQLite store (`.shuttle/shuttle.db`), a DAG scheduler, prompt/artifact rendering, and a worker registry (`intake`, `shell`, `exec`, vendor presets, `manual`). CLI and localhost HTTP share the same engine. Project `cwd` is mutated by workers; `.shuttle/runs/<id>/` holds inputs, artifacts, logs, approvals.

**Tech Stack:** Go 1.22+, `cobra`, `gopkg.in/yaml.v3`, `modernc.org/sqlite` (pure Go), `chi` (HTTP), `text/template`, standard `testing`.

**Spec:** [docs/superpowers/specs/2026-08-25-shuttle-design.md](../specs/2026-08-25-shuttle-design.md) (also [PLAN.md](../../../PLAN.md))

## Global Constraints

- Name/CLI/config/data/module: all `shuttle`; module path `github.com/savitharaghunathan/shuttle`
- Remote (when pushing): `git@github.com:savitharaghunathan/shuttle.git`
- No vendor SDKs in core — config-driven argv only
- One SQLite DB; single-writer v0; no run-level retry/resume
- Human gates before `open_pr` / `ship`; safe echo defaults for those commands
- HTTP listen `127.0.0.1:8080`; no auth
- TDD: failing test → implement → pass → commit per task
- **Commit style:** `git commit -s` (Signed-off-by). Not `-S` (GPG/SSH).
- **Assisted-by:** message trailer `Assisted-by: <model>` (e.g. `Assisted-by: Cursor <cursoragent@cursor.com>`)
- Do not push to remote unless the user asks

### Task 6: Engine — schedule, gates, cancel, retries

**Files:**
- Create: `internal/pipeline/engine.go`, `engine_test.go`
- Modify: `internal/worker/manual.go` (engine treats `worker: manual` as gate — no Execute)

**Interfaces:**
- Produces: `type Engine struct { Store *store.Store; Registry *worker.Registry; Cfg *config.Config }`
- Produces: `StartRun(ctx, params) (runID string, err error)` — load template, init workspace, insert rows, mark roots `ready`
- Produces: `Tick(ctx, runID) (done bool, err error)` — claim/dispatch ready; on manual → `waiting_approval` + run `blocked`
- Produces: `Approve(runID, stageID, msg string) error`, `Reject(...) error`, `Cancel(runID) error`
- Produces: `RunToBlockOrDone(ctx, runID) error` — loop Tick until terminal or blocked

Behavior locked from spec:
- Failure with retries left → backoff 2s → `ready` again
- Timeout → failed attempt
- Cancel: cancel ctx, running→cancelled, pending/ready/waiting_approval→skipped, run→cancelled
- Reject: stage rejected, run failed, downstream skipped
- Approve: stage succeeded, write `approvals/<stage>.md`, unlock dependents, run→running
